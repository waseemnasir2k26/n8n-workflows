**Description:**

A freight forwarder gets quote requests by email and someone retypes each one into a system.
This n8n workflow reads inbound email inquiries — fed here through a webhook with 20 synthetic
sample quotes, never a live mailbox — and extracts shipment details using the Claude API:
origin port, destination port, weight, dimensions, cargo type, incoterm, and a deadline, with
a forced JSON schema so the model can only answer in fields, never in prose. Every email
becomes one row in Postgres keyed on the message id, so a re-run updates the same row instead
of duplicating it. A draft reply echoes the extracted fields back to the sender, marked NOT
FOUND wherever one is missing, and nothing sends on its own — commercial terms need a human,
so the draft is where this workflow stops. Twenty synthetic freight quotes fed this run: FCL,
LCL and air, Karachi to Jebel Ali, Shanghai to Rotterdam, Mundra to Felixstowe, one written
in inches, one due before Eid, one a messy forwarded thread. A Gmail trigger and a Gmail
draft node sit on the canvas, disabled, so you can swap in your Gmail when you are ready.

## LinkedIn

Somebody on your team is retyping freight quotes into a system by hand.

I built an n8n workflow that reads the email, hands it to Claude with a forced schema,
and gets back exactly one shape every time — ports, weight, dimensions, cargo type,
incoterm, deadline, never prose.

Real build gotcha: force the tool, do not ask nicely for JSON. A model told "reply only
with JSON" still wraps a messy forwarded thread in code fences and a paragraph of
hedging. A tool choice that forces the schema removes the option to guess.

Two catches worth saying out loud: anything the model is not sure about comes back
null, never invented, and the reply is only a draft — nothing sends until a person
reads it. Commercial terms need a human, so that is where the workflow stops.
