# Episode 05 — Clinic WhatsApp Booking Agent

A clinic gets appointment requests over WhatsApp in Spanish and English, and a person
retypes each one into a calendar. This n8n workflow takes a patient message, checks a
Postgres-backed slot table, and books an open slot exactly once, because the booking
itself is a single atomic update that can only succeed once per slot. A guard runs in
code before the message ever reaches the model: any symptom, dosage, diagnosis, or
price question is intercepted and handed to a human, by construction,
not by asking the model nicely. Every conversation is held in Postgres chat memory,
keyed to the patient's WhatsApp id, so the agent remembers what was already said. A
duplicate webhook delivery is ignored on purpose, so the same incoming message never
books or answers twice. The scope stays narrow on screen: scheduling and FAQ only, no
symptoms, no diagnosis, no health data stored, and n8n offers no BAA. A WhatsApp
Trigger and a WhatsApp Send node sit on the canvas, disabled, as the swap points for a
real number. Patient messages in this run are simulated patient messages via webhook,
not a live inbox.

## LinkedIn

We shipped a clinic bot that is not allowed to answer a medical question. That is the feature.

I built an n8n workflow that books a patient straight from a WhatsApp message, in
Spanish or English, using an AI agent with real memory. The part worth talking about
is not the booking. It is the line that runs before the agent ever sees the message.

A guard, written in code, reads every incoming message first. Anything about symptoms,
dosage, diagnosis, or price gets pulled out and handed to a human, on purpose, before
the model gets a turn. That is not a prompt instruction the model can talk itself out
of. It is a branch in the workflow.

The booking itself is a single atomic update against a slot table, so a duplicate
WhatsApp delivery can never double book the same slot. Nothing about a patient's
health gets stored. n8n offers no BAA, so the scope stays scheduling and FAQ, and that
boundary is on screen the whole video, not buried in a settings page.
