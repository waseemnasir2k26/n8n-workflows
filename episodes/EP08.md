# Episode 08 — Silent Lane Watchdog

0 errors is not health. A silent lane can be broken, or it can just be quiet. This
free n8n workflow reads the estate's own workflow list, masks every real name into a
pseudonymous `lane_ref` before anything else touches it, then per lane works out
whether an obligation was actually MISSED — scheduled, event-driven, upstream-count,
and manual-run lanes are each judged differently, so a quiet-but-healthy lane (no
demand, switched off, unmeasurable) never becomes a false alarm. On the sanctioned
run (execution 35087, `dry_run` true, Slack disabled) against the live workflow
estate: 63 lanes evaluated, 1 missed against a 60-minute test threshold we set for
this recording (not a real SLA breach), 0 false alarms. The only writes it can make
are a Postgres incident row and an optional Slack message — the Slack node ships
disabled, so the recording you are watching ran in dry run.

**Title:** One lane missed a test schedule we set: the n8n silent lane watchdog

**Description:**

0 errors is not health. A silent lane can be broken, or it can just be quiet.

We rebuilt our internal watchdog pattern as a free, public n8n workflow. Set to
every 6 hours (disabled in this build), it lists active workflows, then checks each
one against an expectation row held in an n8n Data Table: how often it should run,
and what kind of lane it is — scheduled, event-driven, upstream-count, or
manual-run. Silence only becomes an incident when a lane's own obligation was
missed, never from elapsed time alone. A scheduled lane trips when its interval
passes with no run. An event-driven lane never trips on time alone, only on a
missed upstream arrival. A manual-run lane gets a reminder, never an incident.

On a controlled run with a 60-minute test threshold we set: 63 lanes evaluated,
1 missed, 0 false alarms on the quiet one.

An open incident sends one reminder per cooldown window, then closes itself the
moment the lane recovers. Lane names are masked before anything is stored, logged,
or shown on screen. The only writes are a Postgres row and, optionally, a Slack
message — the Slack node ships disabled, so the recording you are watching ran in
dry run.
